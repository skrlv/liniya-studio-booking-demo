## Что проверено по публичному URL

Все **11 групп браузерного сценария прошли**: выбор услуги/совместимого специалиста, запись с вымышленным именем, перезагрузка и сохранение, перенос, отмена, фильтры администратора, Escape, конкуренция двух вкладок и валидация. При 24 одновременных попытках создать пересекающиеся сеансы в одном браузерном хранилище проходит ровно одна. Конкурирующие переносы сохраняют исходную запись проигравшего.

Ширины: 1440, 820, 390, 375 px; переполнения нет. Настольный и мобильный PNG публичной версии просмотрены. Непойманных JavaScript-ошибок и запросов к `/api/` в статическом режиме нет. Использовался отдельный временный браузерный профиль; реальные пользовательские данные не затрагивались. Протокол — [public-browser-verification.json](public-browser-verification.json).

У всех **шести файлов `public/`** по HTTPS получен HTTP 200 и совпадение SHA256 с локальными исходниками. Подпуть репозитория и загрузка ES-модулей работают. Пути `api/catalog`, `server/app.py`, `runtime/studio.sqlite3`, `.env`, `README.md` на Pages вернули 404. Результат — [public-resources-verification.json](public-resources-verification.json).

Позднейшее обновление README и этих протоколов не меняет файлы `public/`. Точный финальный source commit, его Actions run и контрольные суммы ZIP/дерева записываются в итоговом комплекте задачи рядом с исходниками; внутри репозитория ссылки выше фиксируют первую успешную публикацию.

## Граница демонстрации

GitHub Pages показывает браузерный режим: IndexedDB текущего браузера, без общей записи между устройствами. Учебная открытая админка управляет только этими данными. Настоящий локальный backend остаётся отдельным Python/SQLite-сервисом с серверными правами; публикация Pages не превращает его в размещённый сервер. Студия, цены, сотрудники и расписание вымышленные, оплаты и уведомлений нет.
