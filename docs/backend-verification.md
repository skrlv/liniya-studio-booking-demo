# Проверка локального сервера «линия»

Проверено 16 ноября 2026 года. Это учебный локальный Python/SQLite-сервис для вымышленной студии. Публичный GitHub Pages исполняет отдельную браузерную демонстрацию и не использует эту базу.

## Фактический результат

Команда из корня проекта:

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

**25 тестов прошли, 0 ошибок, 0 пропусков.** В проверенном запуске — 0,840 секунды. Каждый тест создаёт отдельную временную SQLite-базу и HTTP-сервер на свободном порту; после теста сервер, поток и временные данные удаляются. Постоянные процессы не остаются.

| Проверка | Подтверждённое поведение |
|---|---|
| 24 конкурентных HTTP-запроса на одинаковый интервал | Ровно один ответ `201`, остальные 23 — `409`; в базе одна запись. |
| 24 конкурентных HTTP-запроса с разным началом пересекающихся двухчасовых сеансов | Ровно один `201`, остальные 23 — `409`. Проверяется пересечение интервалов, а не только одинаковое время начала. |
| Два конкурентных переноса разных записей на пересекающиеся интервалы | Один перенос проходит, другой получает `409`; у проигравшей записи сохранён первоначальный интервал. |
| Конкурирующие создание и перенос на пересекающиеся интервалы | Проходит одно из двух действий. При проигравшем переносе исходная запись остаётся. |

| Владелец | GET/PATCH/DELETE с отсутствующим/чужим ключом получают `403`. Чужая роль в заголовке ничего не меняет. |
| Администратор | Список требует действующий серверный ключ; ключ владельца его не открывает. Администратор может перенести/отменить запись. Без настройки админ отключён (`503`). |

## Контракт повторов

`POST /api/bookings`, `PATCH /api/bookings/:id`, `DELETE /api/bookings/:id` принимают необязательный заголовок `Idempotency-Key`. Формат: 20–128 символов `A–Z a–z 0–9 _ -`; обычный `crypto.randomUUID()` подходит. Для каждого нового действия нужен новый случайный ключ, при сетевом повторе — тот же ключ и те же данные. Без ключа POST не имеет гарантии повтора после потери ответа; пересечения всё равно блокируются.

Успешный ответ сохраняется вместе с транзакцией. Возвращается исходный снимок ответа, даже если запись позже была изменена: актуальное состояние читается через GET. Неуспешные действия не запоминаются. Ключ повтора создания следует беречь так же, как ключ управления записью: владение им позволяет получить исходный ответ создания. Ключи не передаются в URL и не журналируются. В SQLite хранится хеш ключа повтора, публичный снимок ответа и серверный секрет для воспроизведения ключа владельца; сам ключ владельца хранится только в виде хеша. Каталог `runtime/` приватен и исключён из репозитория.

## Запуск

```sh
python3 server/app.py --host 127.0.0.1 --port 8080
```

Локальный адрес: `http://127.0.0.1:8080`. База по умолчанию — `runtime/studio.sqlite3`; путь можно изменить через `--db`. Для кабинета администратора перед запуском задать собственное случайное значение переменной `STUDIO_ADMIN_TOKEN`, минимум 24 символа. Значение не включено в исходники и не выводится сервером. Без переменной запись работает, админ отключён.

## Ограничения

- Сервер привязан к loopback и предназначен для локальной демонстрации. Для публичной рабочей системы нужны выбранный хостинг, HTTPS, полноценная учётная запись администратора/восстановление доступа, эксплуатационные ограничения запросов и резервное копирование.
- Один секретный ключ владельца даёт доступ к одной записи; это демонстрация разграничения, а не внешняя система регистрации клиентов.
- Имена, сотрудники, цены, часы работы и расписание учебные; уведомлений, оплаты и внешней студии нет.
- Безопасность браузерной демонстрационной админки не заявляется: её полномочия ограничены локальными данными браузера. Серверная админка защищена независимо.
