# линия. — сервис записи в студию

Учебный сервис помогает выбрать услугу, специалиста и свободное время, а затем перенести или отменить запись.

**Версия 1.0.0, 16 ноября 2026.** Браузерная демонстрация и отдельный локальный сервер реализованы и проверены. Публичная версия пока **не опубликована**: требуется создание отдельного репозитория и включение GitHub Pages. Планируемое имя — `skrlv/liniya-studio-booking-demo`; адрес не является подтверждённой ссылкой.

## Что можно проверить

- Три услуги с разной длительностью и демонстрационной стоимостью.
- Три вымышленных специалиста; доступны только подходящие выбранной услуге.
- Расписание на 30 дней с завтрашнего дня, 10:00–20:00 по Москве, шаг 30 минут. Сеанс должен целиком помещаться в рабочие часы.
- Создание записи, история после перезагрузки, перенос к другому специалисту/на другую дату и время, отмена.
- Кабинет администратора: список, фильтры по сотруднику, дате и статусу, перенос, отмена, количество записей и сумма учебных цен. В браузерном режиме также доступна очистка демо с подтверждением.
- Защита от пересечения интервалов одного специалиста. Смежные сеансы и одинаковое время у разных специалистов разрешены.
- Адаптивная вёрстка, клавиатурный фокус, закрытие диалогов Escape, reduced motion и текстовое отображение введённого имени.

## Два разных режима

| | Браузерная демонстрация | Локальный сервер |
|---|---|---|
| Хранение | IndexedDB этого браузера, максимум 200 записей | Общая SQLite-база запущенного сервера |
| Другая вкладка | Видит ту же базу в одном профиле/источнике сайта | Видит общую доступность |
| Другой браузер/устройство | Собственные независимые данные | HTTP API использует ту же базу; сервер доступен только с этого компьютера |
| Управление записью | Все записи этого браузера доступны в демо | Секретный ключ конкретной записи; администратору нужен отдельный ключ |
| Администратор | Открытый учебный кабинет, без имитации авторизации | Права проверяет сервер; без настройки кабинет отключён |
| Защита от пересечений | Проверка и запись внутри одной IndexedDB-транзакции | SQLite-транзакция и триггеры INSERT/UPDATE |

Браузерная демо-админка не даёт серверных прав. GitHub Pages отдаёт только файлы `public/`, не запускает Python и не хранит общую базу. Записи разных устройств на Pages не синхронизируются. Очистка данных сайта удаляет браузерные записи и сохранённые ключи управления серверными записями.

**Студия, сотрудники, цены и расписание вымышленные.** Используйте вымышленное имя. Контакты не собираются, уведомления не отправляются, оплаты и реальной брони в студии нет. Внешние CRM, почта и мессенджеры не подключены.

## Быстрый запуск

Нужен Python 3.9 или новее. Для работы сервиса сторонние зависимости не нужны. Выполняйте команды из каталога этого проекта.

Браузерная демонстрация:

```sh
python3 -m http.server 8762 --bind 127.0.0.1 --directory public
```

Откройте локальный адрес `http://127.0.0.1:8762/?demo=1`. Параметр `demo=1` нужен для статического просмотра на localhost. На GitHub Pages режим определяется автоматически. Для остановки нажмите Ctrl+C.

Локальный сервер:

```sh
python3 server/app.py --port 8080
```

Откройте локальный адрес `http://127.0.0.1:8080`. Сервис сохранит базу в `runtime/studio.sqlite3`; она переживает перезапуск. Другой путь задаётся `--db /путь/к/базе.sqlite3`. На localhost сбой API показывается как ошибка, автоматической подмены браузерным режимом нет.

Чтобы включить админку, задайте перед запуском `STUDIO_ADMIN_TOKEN` собственным случайным значением длиной не менее 24 символов. В macOS Terminal можно ввести его скрыто:

```sh
read -r -s STUDIO_ADMIN_TOKEN
export STUDIO_ADMIN_TOKEN
python3 server/app.py --port 8080
```

После первой команды введите придуманный ключ и нажмите Enter; символы не отображаются. Тот же ключ введите в кабинете администратора. Сервер не печатает его, интерфейс хранит административный ключ только в памяти открытой страницы. Без переменной сервер работает с отключённым администратором. Файл `.env.example` — справка о переменной; сервер не загружает `.env` автоматически.

## Сценарий на 2 минуты

1. Оставьте «Стрижка и форма», выберите Анну, завтрашний день и 10:00.
2. Введите «Демо Гость», подтвердите запись и откройте «Мои записи». После перезагрузки запись остаётся.
3. Нажмите «Перенести», выберите 12:00 и подтвердите. Время 10:00 снова доступно.
4. Откройте «Администратор» (в серверном режиме введите ключ), проверьте фильтры и отмените запись. В истории останется статус «Отменено».
5. На Pages/в статическом режиме откройте вторую вкладку того же браузера: записи общие между вкладками. В другом браузере будет отдельное пустое демо.

## Проверки

Сервер и защита от пересечений, без установки пакетов:

```sh
python3 -m unittest discover -s tests -p 'test_*.py' -v
```

25 проверок включают 24 одновременных создания, разные пересекающиеся начала, конкурирующие переносы, создание против переноса, сохранение исходной записи при отказе, смежные интервалы, владельческие/админские права, повторы запросов и ограничения выдачи файлов. Детали — [backend-verification.md](docs/backend-verification.md).

Для проверки статических файлов нужен Node.js 20+:

```sh
npm run check
```

Браузерные проверки требуют Node.js 20+, бесплатный Playwright и Chromium:

```sh
npm ci
npx playwright install chromium
npm run test:browser
npm run test:server-ui
```

Оба сценария сами поднимают сервер на свободном порту и останавливают его. Используют временную базу и отдельный чистый браузерный профиль; реальные записи не затрагиваются. На Linux установите системные зависимости командой `npx playwright install --with-deps chromium`. Для машинного чтения сохранены [браузерные проверки](docs/browser-verification.json) и [проверка интерфейса с сервером](docs/server-browser-verification.json). Проверены ширины 1440, 820, 390 и 375 px.

Проверка опубликованной версии после развёртывания:

```sh
DEMO_URL='https://skrlv.github.io/liniya-studio-booking-demo/' npm run test:browser
```

Эта команда пока не выполнялась: публикация ожидается. Снимки текущей локальной версии находятся в `docs/preview-*.png`.

## Структура и API

- `public/` — интерфейс, стили, относительные пути, единый `catalog.json`, браузерный и серверный адаптеры.
- `server/app.py` — HTTP API, SQLite, проверка полномочий и атомарные изменения.
- `tests/` — серверные, браузерные и статические проверки.
- `docs/` — результаты проверок и снимки интерфейса.
- `.github/workflows/pages.yml` — проверки и публикация только `public/`.

API: `GET /api/catalog`, `GET /api/slots`, `POST /api/bookings`, `GET/PATCH/DELETE /api/bookings/:id`, `GET /api/admin/bookings`. Ключ владельца передаётся `X-Booking-Token`, администратора — `Authorization: Bearer …`. Недопустимые данные дают `400`, отсутствие прав — `403`, пересечение — `409`. Ключи не передаются в URL.

Изменяющие запросы принимают `Idempotency-Key`: новый случайный ключ для нового действия, тот же ключ и тело для повтора. Успешный ответ сохраняется в той же транзакции. Повтор с другими данными даёт `409`. После успешного повтора актуальное состояние можно прочитать через GET. Интерфейс автоматически повторяет сетевой сбой один раз; при повторной ошибке хранит ключ для того же действия до закрытия страницы. Если закрыть страницу после потери ответа создания, восстановление управления потребует администратора. Полный контракт и границы — в отчёте серверных проверок.

Это локальный демонстрационный сервер. Для рабочей студии отдельно потребуются выбранный серверный хостинг, HTTPS, полноценные учётные записи и восстановление доступа, резервное копирование и эксплуатационные ограничения запросов. Платные сервисы не подключались.

## Публикация

Комплект рассчитан на отдельный репозиторий `liniya-studio-booking-demo`, ветку `main`, Settings → Pages → Source: **GitHub Actions**. Workflow проверяет сервер, статические пути и браузерные сценарии, загружает только `public/` и развёртывает официальный Pages artifact. Пути `./…` работают под базовым путём `/liniya-studio-booking-demo/`.

Использованы официальные действия `actions/configure-pages@v5`, `actions/upload-pages-artifact@v4`, `actions/deploy-pages@v4` согласно [документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages), проверенной 16.11.2026. Наличие workflow не означает успешный деплой. Публичный URL и Actions пока не проверены, потому что репозиторий ещё не создан.
